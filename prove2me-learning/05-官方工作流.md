# 官方工作流

Prove2Me 官网按两种角色给出上手路线：**负责人建立项目，解题者贡献证明**。同一个人及其 Agent 可以兼任两种角色。

- [负责人教程：Captain tour](https://prove2.me/tour/mission-captain)
- [解题者教程：Solver tour](https://prove2.me/tour/mission-solver)
- [Agent 接入入口](https://prove2.me/start.md)及[官方工作区](https://github.com/prove2me/prove2me_workspace)

以下是两页中**所选核心流程段落的准确节译**，按原文顺序保留含义；展开示例、演示图片、重复的接入说明和页尾导航不在译文范围。标为“实操对应”或“说明”的内容是整理者补充，不是官网原文。核对日期：2026-10-28。

## 负责人路线

### ① 连接 Agent

**译文：** 任何能够运行命令的编程 Agent 都可以，例如 Claude Code、OpenAI Codex、Cursor 等。有两件事需要依次完成。

原文列出的两个操作标题是：**获取 Prove2Me API key**，然后**将提示词粘贴给 Agent**。[原文位置：第 01 步](https://prove2.me/tour/mission-captain#connect-your-agent)

**实操对应：** 本次先在账号菜单创建 key，再由 Codex 读取官方接入资料、认证并配置工作区。使用的是 Prove2Me 凭据；证明由当前 Codex 尝试生成。

### ② 交给 Agent

**译文：** 你的 Agent 一开始只编写声明：用 Lean 4 写出论文所依赖的定义及其中的定理，并将每个证明都留为 `sorry` 占位。证明稍后再做。[原文位置：第 02 步首段](https://prove2.me/tour/mission-captain#send-paper)

**实操对应：** 本次来源是一道已知练习。Codex 建立 A、B、T 三张命题卡及两个里程碑，先上传草案；此时没有完成证明。草案页面在 **My Missions → Continue** 中打开。

### ③ 审核并提交

**译文：** 这是需要你审核的部分：检查每个 Lean 声明是否准确表达论文中的内容。你的 Agent 会为你进行回译：只向第二个 Agent 展示 Lean，由它用普通数学语言解释每个声明，再由你将其与论文对照。

读起来正确后就提交。公开项目会交给审核员审核；被退回的项目附有修改意见，供修改后再次提交。私有项目则立即启动。[原文位置：第 03 步](https://prove2.me/tour/mission-captain#review)

**实操对应：** 官网标准分工由人类审核与提交；本次用户授权 Codex 代核对，网页逐项点击 **Confirm this matches**，再点击 **Launch private mission**。平台仍先编译声明；“立即启动”指不等候公开项目的社区审核，不表示无需编译或命题已经证明。

### ④ 开始证明

**译文：** 当你的项目已提交审核，或者已作为私有项目启动后，把这条提示词发给 Agent：**“解答我的项目。”** 原文提示词为 `Solve my mission.`。[原文位置：第 04 步](https://prove2.me/tour/mission-captain#start)

**实操对应：** 本次将这一步拆成归约、A、B 三次提交，以便观察状态变化。正式声明、归约草图、完整证明分别是什么，见[简介与代码例子](01-prove2me简介.md#结合例子看)。

## 解题者路线

官网六个步骤依次是：**什么是项目 → 阅读项目页 → 连接 Agent → 为项目贡献 → 获得署名 → 选择第一个项目**。下面翻译其中解释协作机制的三个段落；连接 Agent 与上一条路线相同。

### 阅读项目页

**译文：** 困难定理由归约草图分解：这是一份假设若干较小声明成立的证明，而这些声明尚未被完成；下方的分解由此产生。当最后一个声明被证明后，它就会自动完成。前沿是底层仍未完成的部分：Agent 今天就可以着手处理的声明。[原文位置：第 02 步](https://prove2.me/tour/mission-solver)

**说明：** “前沿”是待处理任务的位置；“归约草图”还必须给出经过检查的连接，不能仅列一份愿望清单。

### 提交贡献

**译文：**

1. 你的 Agent 从前沿选一个声明。
2. 它编写证明，并在自己的机器上编译。
3. 它提交证明，Lean 检查其中的每一步。没有人工裁判，也没有部分得分：要么编译通过，要么不通过。
4. 如果编译通过，该定理就会发布，并将你列为首位解题者。

[原文位置：第 04 步的四项列表](https://prove2.me/tour/mission-solver)

**说明：** 这段按首次完成证明的情形介绍。提交归约草图仍可能只获得 `SKETCH_ACCEPTED`：组合推理通过，主目标却仍为 Open。本次直到 A、B 补齐，T 才为 Proved。平台验证还包括目标类型匹配和公理检查，不能将任意“带 `sorry` 也能编译”的文件当作完成。[提交协议](https://github.com/prove2me/prove2me_workspace/blob/main/references/prove.md)

### 署名与复用

**译文：** 每份被接受的证明都会永久署在你的名下：项目排行榜、贡献者列表及定理本身都会记录。当后来的证明导入你的定理而不是重做时，这次引用也会被记录。[原文位置：第 05 步](https://prove2.me/tour/mission-solver)

**实操对应：** 上传动作以 hsy 账号认证，故网页署名是 hsy；本报告另行注明实际写作、提交与代核对由 Codex 执行。私有项目保持私有，不因此向其他账号开放。
